# M13 剩余审计整改（本地未提交）

基线为 `feat/dual-engine` / `2ed80ac`。不代表发布就绪，未推送或发布。

## 第一批：启动、状态与目录

- Deep 启动只对已知输入校验错误提供具体修正提示；未知错误与路径异常继续脱敏。
- Windows 启动改为最多 60 秒等待 UI 和经 UI 代理的 API 健康响应，未就绪不打开浏览器；不再只睡两秒。
- 海外指数无数据或请求失败时保留面板与状态提示，不填零、不隐藏。
- `non_trading_day` 保留上游非交易日状态；原有复盘日期算法不变。
- 使用已有生成器重建端点目录：117 个端点、30 层，与注册表逐项核对。

验证：后端定向 28/28，前端定向 2/2，类型检查通过；独立 Codex 范围审查无可行动回归。
Windows PowerShell 尚未实际运行；本机只验证就绪探针与脚本接线，不能声称 Windows 真机通过。

## 第二批：风险统计与持有对照

- Sortino 分母与风险透视共用目标收益为零的下行偏差：全部观测参与分母，正收益贡献零，不再计算负收益内部标准差。
- 零下行偏差、空样本或不可计算时 Sortino 返回 `null`，不再加微小常数造出巨大比率。
- 默认自基准改为初始等权持有：每个标的首次有效报价前留现金，之后固定份额、缺报价延用前值；无每日再平衡、无费用。摘要明确说明这些边界。
- WorkBuddy 只读启动探针从每步五秒改为十五秒上限；超时仍是检测失败，不冒充退出登录。真实冷启动曾接近五秒，合成延迟测试复现旧失败。

计算口径参考 [Sortino: A Sharper Ratio（CME 托管）](https://www.cmegroup.com/education/files/rr-sortino-a-sharper-ratio.pdf)。原有首个权益观测的收益序列约定未在本批修改。

验证：回测 185/185；独立 Codex 范围复审无可行动回归。反例：一资产翻倍再减半、另一资产不变，持有对照收益为零，原每日再平衡结果为 12.5%。

## 第三批：路径与诊断器

CSV / JSON 序列入口统一拒绝含 `.`、`..`、重复分隔符的歧义路径；规范路径与既有计算身份不变。
数据源诊断器将缺少状态、结构错误和解释器失败记录为 `crash`，不让汇总进度二次崩溃。
定向 Python 36/36；独立 Codex 复审无可行动回归。损坏诊断结果如实记录，不改写为数据源空集。

## 第四批：权重约束

约束最多迭代 50 次，并在返回前同时核验各项上限、下限与分组条件；不满足或不可行时明确报错。
保留方向、不激活零持仓、不增加总敞口；资金不足以满足下限时不伪报成功。这不是一般组合优化器。
排列顺序、不可行组合及非有限值回归通过；回测 209 项通过，独立 Codex 范围审查无可行动回归。

## 第五批：跨期对照与行业契约

行情观察字段由金融插件声明；同来源的日期型观察按最新日期比较，页面与报告均显示旧、新资料期。
非观察字段仍严格按资料期比较，不混合来源。数字校验排除章节由插件声明，不在 Core 写死中文标题。
注册期校验、第二垂类与旧接口默认值保留。定向 80 项通过，独立 Codex 范围审查无可行动回归。

## 第六批：PE 当前值与历史序列来源

PE 分位计算在报告主标题后披露当前值来源、历史序列来源与对应计算 id；同源也显示，不根据相近值猜来源。
来源不完整就写未核实。提示词和生产校验共用生成规则；损坏计算记录交给已有 schema 校验，不引发 TypeError。
定向 PE 四项及编排回归 32 项通过，独立 Codex 收口复审无可行动回归。
