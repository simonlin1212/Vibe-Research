## 产品改动

1. 报告中的证据与计算编号可以点击定位到同次运行的附录行；折叠时自动展开，键盘 Enter 同样可用。
   计算输入的引用也能继续定位。只有附录实际登记的 id 才变成链接，不推断缺失出处。
2. 按 Markdown 语法树处理文本，不改现有链接、代码或图片；保留脚注返回 id 与无障碍标签。
   HTML 不执行、远程图片不加载、危险链接仍由原安全处理拦截。未通过最终校验的报告及附录仍不可见。
3. 保留 17 条路由、原 13 个主栏目和 7 个子栏目。首页/接入页即时加载，14 个业务路由入口按需加载，
   页面切换有加载反馈，直接打开深层地址有初始提示，原错误恢复页保留。
4. 首屏主 JS 从 V2 验收约 1.31 MB 降为 **584.93 kB**（gzip 约 183.20 kB，约减少 55%）。
   这是构建产物大小，不是弱网首屏耗时实测。Signals 图表块仍约 569.52 kB，两个大块的体积警告保留。
5. 发布清单纠正旧状态：许可证 MIT、真实仓库 clone 地址早已存在；模板核对日期不等于真实模型矩阵通过。

## Claude Code + Opus 5 真实验证

CLI 2.1.261。先按 [Claude 官方模型配置说明](https://support.claude.com/en/articles/11940350-claude-code-model-configuration)
核实 `claude-opus-5`，短调用实际成功，主回答模型为该标识。CLI 的 modelUsage 同时含 Haiku 记录，
所以只声称主模型固定为 Opus 5，不宣称所有辅助请求都没有其他模型。

完整研究 `m15-claude-opus5-full-1`：独立数据根 `.local/m15-claude-opus5-full`，300308，
`endpoint_scope=full`，无夹具播种、六阶段；引擎 `local-agent:claude`，来源 `cli-claude/subscription_login`。
验证用本地忽略目录包装入口固定模型，产品源码与全局默认设置不变。模型标识与时间记录在
`.local/reviews/m15-opus5-usage.jsonl`，不记录提示词、账户 token 或完整模型输出。

截至本段初次记录，运行仍在风险阶段，**未宣称整场通过**。前三次财务尝试保留在事件流：
第一次“有必需项缺口却标 complete”被拒；第二次有计算复算退出码 3；第三次修正后校验通过，
阶段如实为 incomplete。最早累计资料缺上期，不能拆出最早季度，但其余可用季度可形成 TTM。
这不构成隐藏缺口或降低 validator 要求的理由。最终结果将在运行结束后追加。

另行执行 Claude core/profile 中止验证，独立 runId 与临时数据根，不影响完整研究；原始记录见
`.local/reviews/m15-claude-cancel-*-result.log`。首轮验收装置因服务最小环境不透传 `CLAUDE_BIN`
而未通过固定模型屏障，已终止且不计入 Opus 5 验收；后继改为仅本次进程的独立 PATH 包装入口。

最终采用 `m15-claude-cancel-3`：明确匹配自有后代中的 Claude 可执行路径及末尾
`--model claude-opus-5`，同时观察到实际 Node MCP 进程，并在取消前断言三份业务取数文件存在。
停止后 **825 ms** 确认 cancelled / exit 3；观察到的 **6 个进程**均退出，**5 份取数 JSON** 哈希不变，
report=false。不是“所有可能出现过的进程”或“服务端计费已经停止”的证明。
验收装置首轮独立审查发现编号匹配过宽、空哈希可假绿及包装器长参数形式遗漏，均修正；复审
`No actionable regressions`。范围仅忽略目录验收脚本，产品源码未改。
