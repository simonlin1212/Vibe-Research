## 1. 用户只做一个初始选择

第一次打开产品时，只回答“AI 从哪里来”：

- 订阅：Codex、Claude Code 或 WorkBuddy / CodeBuddy；
- API：OpenAI、DeepSeek、Qwen、GLM、Kimi、MiMo 或兼容端点。

连接探针成功后保存一份全局 AI 来源，所有页面共用。用户不用理解 provider、Harness、Quick、Deep 或
底层引擎。没有明确保存过配置时，产品必须回到“接入 AI”，不能借后端默认配置偷偷替用户选择。

## 2. Agent 默认开启

AI 来源卡下面固定显示第二张“Vibe Research Agent”卡，默认开启：

- 开启：维持本地上下文、调用工具、推进任务、显示进度、处理失败并保存可继续的研究过程；
- 关闭：直接调用已经验证的模型 API，只做不需要 Agent 工具和任务状态的轻量能力。

订阅登录不能关闭 Agent，因为订阅凭据不是可以任意调用的裸 API key。API provider 也只有在真实探针确认
直连协议、鉴权和输出可用后，才开放关闭开关。切换模式不要求重新填写 key。

## 3. 能力矩阵

| 能力 | Agent 开启 | 模型直连 |
|---|---:|---:|
| 页面浏览、数据刷新、确定性计算 | 可用 | 可用 |
| 普通问答、标题翻译、现有材料定位 | 可用 | 可用 |
| 本地工具调用与连续任务状态 | 可用 | 不可用 |
| 六阶段研究、多空辩论、Agent 回测、资料转写 | 可用 | 不可用，明确提示一键开启 Agent |
| Agent 任务记忆与后续迭代 | 可用 | 不可用 |

系统内部仍可按任务结构选择 deterministic / quick / deep，但界面不再让普通用户做这道工程选择。
上述 Agent 列是产品能力集合，不代表每个模型都能完成所有问题：Claude/WorkBuddy 的辩论、Agent 回测、资料转写
已完成对应 CLI 适配和指定输入实跑，详见 [M12 验收](跨来源业务验收_M12_2026-09-05.md)。不能暗中切来源；首页三个任务入口已跳转今日复盘、公司研究、已有研报的受控页面，
用户补充信息并确认后才执行。下方普通聊天不自动取数、不抓全网研报，不把回答冒充任务完成。
直连模式碰到 Agent 专属能力时必须在副作用发生前返回 `agent_required`，不得静默切回 Agent，也不得降级成
一段看似完成的普通回答。

## 4. 运行时身份必须说真话

- Codex 订阅由 OpenAI Codex Harness 承载；
- Claude.ai 订阅由本机 Claude Code Agent 承载，不叫 Codex Harness；
- WorkBuddy / CodeBuddy 账号由本机 CodeBuddy Code Agent 承载，不叫 Codex Harness；
- 模型 API 在 Agent 模式下作为 Codex Harness 的模型来源，在直连模式下直接由受限传输层调用；
- Claude Code 与 WorkBuddy / CodeBuddy Agent 可运行完整 A 股六阶段研究；每个阶段使用独立 CLI 会话，
  关闭内建工具，只开放 `list_run_files / read_run_file / calculate / write_stage / write_report` 五个产品 MCP 工具；
- 本机订阅 Agent 的运行清单明确标为 `local_agent / cli_subscription / per_stage_session / host_events`，
  不冒充具有 Codex lifecycle hooks、skills 或线程连续性的 Codex Harness；

每次请求都绑定已保存的 `source + executionMode`。路由指纹同时包含 AI 来源与执行方式，防止先按某个
provider / Agent 路由，执行时再偷换成另一家模型或直连。

## 5. 隐私与保存边界

- API key 为了免重复填写，会持久保存在当前浏览器的本机 `localStorage`；它不是系统钥匙串，也不承诺加密，
  只建议在可信个人电脑使用，共享电脑用完应主动清除；
- 后端不把 key 写入仓库、配置、日志、事件账本或研究产物；
- 研究子进程只接收 provider 元数据，真实 key 经 provider 自己声明的环境变量传入；
- 订阅登录沿用各自运行时的隔离登录态，不把一种订阅凭据转换成另一种 API。
- CodeBuddy 登录探针只向产品返回登录布尔，不返回账号或 token；普通回答关闭全部工具与 MCP，六阶段研究
  关闭内建工具、只加载产品受控 MCP；用户配置、自动记忆与后台任务保持关闭。WorkBuddy 内置旧 CLI
  缺少无会话参数时，凭据只在内存中转给一次性临时用户目录中的回答进程，结束后删除该目录。
