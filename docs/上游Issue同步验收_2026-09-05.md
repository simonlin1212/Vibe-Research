## 实施与兼容性取舍

1. **#44 连接修复**：`chat.ts` 将产品运行环境交给 MCP 发现；`runner.ts` 在发现前创建产品配置目录并强制
   `CODEX_HOME=cfg.codexHome`。回归测试用临时外部 MCP 配置证明不会加载错误的全局配置；不读取或复制个人凭据。
2. **LAN 默认关闭**：`VRA_LAN=1` 才让 Vite 绑定 `0.0.0.0`。POSIX / Windows 启动器移除覆盖 Vite 的 UI host 参数，
   后端 API 仍绑定 `127.0.0.1`。本轮测试实际监听始终为回环地址，没有替用户开启 LAN。
3. **保留跨站防护**：LAN 代理在添加后端 Bearer 前校验 Origin 与 Sec-Fetch-Site，再归一化合法同源请求的 Origin。
   恶意来源、null 来源与跨站请求返回 403，不能到达测试后端。LAN 不是多用户权限系统；可达同网用户可操作工作区，
   HTTP 不加密，不可直接暴露公网。默认关闭与这些限制在中英文说明中明确展示。
4. **自托管不等于任意 HTTP**：复用本分支既有地址规则，远程模型仍要求 HTTPS，只有 localhost / 127.0.0.1 / [::1]
   可用 HTTP。新增 selfhosted 模板要求替换占位路径与显式模型名，状态未实测；未提供协议转换器，也不自动开放直连。
   “本机”指产品后端所在机器。没有宣称某个 Ollama / LM Studio / vLLM 模型已经满足 Responses 或工具调用契约。
5. **HTTP 会话兼容**：除上游回测页之外，补齐当前分支的报告聊天与页面分析/笔记反思，避免非安全上下文缺少
   `crypto.randomUUID` 而无法发起操作。生成的是消息/会话标识，不作为鉴权令牌或安全随机数使用。
6. **保留一次接入**：设置中一次选择 API 或订阅来源，Agent 默认开启。没有引入第二套聊天与研究配置向导。
